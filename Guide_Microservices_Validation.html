Dockerfile — Conteneurisation

Docker Compose 2pts

Un Dockerfile décrit comment construire une image Docker pour un service. Chaque microservice possède son propre Dockerfile.

Principe : Le Dockerfile liste les instructions pour créer une image. Cette image est ensuite instanciée en container lors du docker compose up.

Dockerfile — Services Spring Boot (Java)

Tous les services Java partagent le même pattern. Ils utilisent une image JRE légère Alpine.

Important : Ces Dockerfiles ne compilent PAS le code. Ils copient le JAR déjà compilé depuis target/. Il faut donc lancer mvn clean package -DskipTests depuis backend/ avant de faire docker compose up --build.
dockerfile backend/auth-service/Dockerfile  |  backend/claim-service/Dockerfile  |  backend/retake-service/Dockerfile  |  backend/eureka-server/Dockerfile  |  backend/gateway-service/Dockerfile 
# Image de base : JRE Java 21 sur Alpine Linux (légère ~85MB)
FROM eclipse-temurin:21-jre-alpine

# Répertoire de travail dans le container
WORKDIR /app

# Copier le JAR compilé (mvn clean package produit target/*.jar)
COPY target/*.jar app.jar

# Port exposé (documentaire, pas fonctionnel sans -p ou docker-compose)
EXPOSE 8083   # 8761 pour eureka, 8080 pour gateway, 8081 claim, 8082 retake

# Commande de démarrage du container
ENTRYPOINT ["java", "-jar", "app.jar"]

Dockerfile — ML Service (Python FastAPI)

Le service ML est en Python et utilise FastAPI. Son Dockerfile fait la compilation pip directement.

dockerfile backend/ml-service/Dockerfile 
# Image Python 3.11 allégée
FROM python:3.11-slim

WORKDIR /app

# Copier et installer les dépendances (FastAPI, scikit-learn, etc.)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copier tout le code source
COPY . .

# Créer les dossiers pour les modèles ML et les données
RUN mkdir -p /app/models /app/data

EXPOSE 5000

# Lancement avec Uvicorn (serveur ASGI pour FastAPI)
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "5000"]

FROM

Image de base (OS + runtime). Alpine = image minimale, sécurisée et légère.

WORKDIR

Définit le répertoire courant dans le container. Toutes les instructions suivantes s'exécutent depuis là.

COPY

Copie des fichiers de la machine hôte vers l'image Docker.

EXPOSE

Documentation du port. Docker Compose s'en sert mais il faut aussi mapper dans ports:.

Docker Compose orchestre plusieurs containers ensemble. Il définit les services, leur configuration, leurs dépendances et leur réseau commun.

Concepts clés Docker Compose

depends_on + condition

Garantit l'ordre de démarrage. service_healthy attend que le healthcheck passe avant de démarrer le service dépendant.

networks (bridge)

Tous les services dans platform-network se voient par leur nom de service (ex: mysql, eureka-server) à la place de l'IP.

volumes

Persistance des données. Sans volume, toutes les données disparaissent à chaque docker compose down.

environment

Variables d'environnement injectées dans le container. Elles surchargent application.properties dans Spring Boot.
Commandes essentielles :
cd backend && mvn clean package -DskipTests → Compiler tous les JAR
docker compose up --build → Construire et démarrer tous les containers
docker compose down -v → Arrêter et supprimer les volumes
docker compose logs -f auth-service → Suivre les logs d'un service
docker ps → Lister les containers actifs

Eureka Server — Service Discovery

1 pt

Eureka est un serveur de découverte. Chaque microservice s'enregistre sur Eureka au démarrage. Quand un service veut appeler un autre, il demande son adresse à Eureka au lieu de la coder en dur.

1 pt

Le Gateway est le point d'entrée unique de toute l'application. Il reçoit toutes les requêtes du frontend et les route vers le bon microservice. Il gère aussi le CORS (Cross-Origin Resource Sharing).

  port: 8080

spring:
  application:
    name: gateway-service

  cloud:
    gateway:
      # ── CORS global : autorise le frontend Angular ──────────────
      globalcors:
        cors-configurations:
          '[/**]':
            allowedOrigins:
              - "http://localhost:4200"   # URL du frontend Angular
            allowedMethods: [GET, POST, PUT, PATCH, DELETE, OPTIONS]
            allowedHeaders: ["*"]
            allowCredentials: true

      # ── Routes : règles de routage ───────────────────────────────
      routes:
        # Auth Service — toutes les requêtes /auth/**, /user/**, /api/students/**
        - id: auth-service
          uri: http://auth-service:8083        # Nom container dans Docker
          predicates:
            - Path=/auth/**, /user/**, /api/students/**

        # Claim Service
        - id: claim-service
          uri: http://claim-service:8081
          predicates:
            - Path=/api/claims/**

        # Retake Service
        - id: retake-service
          uri: http://retake-service:8082

            - Path=/api/retake-requests/**

Sécurité — JWT + Spring Security

2 pts

La sécurité est gérée par JWT (JSON Web Token). L'auth-service génère un token signé à la connexion. Le frontend l'envoie dans chaque requête via le header Authorization: Bearer <token>.

Flux d'authentification complet

1. Frontend
→
POST /auth/login {email, password}
2. AuthService
→
Vérifie email/mot de passe avec BCrypt
3. JwtService
→
Génère JWT signé HMAC-SHA512 (id, name, role, email)
4. Réponse
→
{accessToken, tokenType:"Bearer", expiresIn:86400}
5. Requêtes suivantes
→
Authorization: Bearer eyJ0eXAi...
6. JwtAuthFilter
→
Valide le token à chaque requête reçue

JwtService — Génération et validation du token

java backend/auth-service/src/main/java/tn/english/school/authservice/service/JwtService.java 
@Service
public class JwtService {

    @Value("${jwt.secret}")
    private String secret;            // Clé secrète (64+ caractères)

    @Value("${jwt.expiration}")
    private long expirationMs;         // 86400000 = 24h

    // Génère le token JWT avec les claims de l'utilisateur
    public String generateToken(AppUser user) {
        long nowMs = System.currentTimeMillis();
        return Jwts.builder()
                .header().type("JWT").and()
                .claims(Map.of(
                    "id",   user.getId(),          // ID utilisateur
                    "name", user.getFirstName() + " " + user.getLastName(),
                    "role", user.getRole().name() // STUDENT ou ADMIN
                ))
                .subject(user.getEmail())         // sub = email
                .issuedAt(new Date(nowMs))
                .expiration(new Date(nowMs + expirationMs))
                .signWith(getKey())               // HMAC-SHA512
                .compact();
    }

    public boolean isTokenValid(String token) {
        try {
            return extractClaims(token).getExpiration().after(new Date());
        } catch (Exception e) { return false; }
    }
}

JwtAuthFilter — Filtre appliqué à chaque requête

java backend/auth-service/src/main/java/tn/english/school/authservice/config/JwtAuthFilter.java 
@Component
public class JwtAuthFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                        HttpServletResponse response,
                                        FilterChain filterChain) {
        final String authHeader = request.getHeader("Authorization");

        // Pas de token → passe au filtre suivant (accès public)
        if (authHeader == null || !authHeader.startsWith("Bearer ")) {
            filterChain.doFilter(request, response);
            return;
        }

        final String jwt = authHeader.substring(7); // Enlève "Bearer "

        if (jwtService.isTokenValid(jwt)) {
            String email = jwtService.extractEmail(jwt);
            // Charge l'utilisateur et l'authentifie dans le SecurityContext
            var userDetails = userDetailsService.loadUserByUsername(email);
            var authToken = new UsernamePasswordAuthenticationToken(
                    userDetails, null, userDetails.getAuthorities());
            SecurityContextHolder.getContext().setAuthentication(authToken);
        }
        filterChain.doFilter(request, response);
    }
}

SecurityConfig — Règles d'accès

java backend/auth-service/src/main/java/tn/english/school/authservice/config/SecurityConfig.java 
@Configuration @EnableWebSecurity
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        return http
            .csrf(AbstractHttpConfigurer::disable)      // API REST → pas de CSRF
            .sessionManagement(s -> s
                .sessionCreationPolicy(SessionCreationPolicy.STATELESS)) // JWT = stateless
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/auth/login", "/auth/register").permitAll() // Public
                .anyRequest().authenticated()                              // Reste : JWT requis
            )
            .authenticationProvider(authenticationProvider)
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class)
            .build();
    }
}

package tn.english.school.retakeservice.client;

import org.springframework.cloud.openfeign.FeignClient;

// "claim-service" = nom enregistré sur Eureka (spring.application.name du claim-service)
// Feign demande à Eureka l'adresse IP/port réelle de claim-service
@FeignClient(name = "claim-service")
public interface ClaimClient {

    // Récupère une réclamation par son ID — GET http://claim-service/api/claims/{id}
    @GetMapping("/api/claims/{id}")
    ClaimDTO getClaimById(@PathVariable("id") Long id);

    // Lie un retake à une réclamation — PUT http://claim-service/api/claims/{claimId}/link-retake/{retakeId}
    @PutMapping("/api/claims/{claimId}/link-retake/{retakeRequestId}")
    ClaimDTO linkRetakeRequest(
        @PathVariable("claimId") Long claimId,
        @PathVariable("retakeRequestId") Long retakeRequestId
    );
}
Avantage OpenFeign : Il suffit de déclarer une interface. Feign génère automatiquement le code HTTP, gère la sérialisation JSON, et utilise Eureka pour résoudre l'adresse du service cible. Pas besoin de RestTemplate manuel.

ML Service — Microservice Python FastAPI

Technologie avancée 2 pts + Valeurs ajoutées 2 pts

Le ML Service est un microservice Python FastAPI qui expose une API REST pour prédire les performances académiques des étudiants via des modèles de Machine Learning (Random Forest + K-Means).

Endpoints exposés par le ML Service

MéthodeEndpoint MLVia GatewayDescription
GET/health/api/ml/healthVérification santé service
GET/model-info/api/ml/model-infoMétriques du modèle
POST/predict/api/ml/predictPrédiction pass/fail (Random Forest)
POST/cluster/api/ml/clusterClustering K-Means (At-Risk/Average/High)
POST/analyze/api/ml/analyzepredict + cluster en un seul appel

Point d'entrée — app/main.py

python backend/ml-service/app/main.py 
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
import joblib, numpy as np

# Modèle de données d'entrée (Pydantic valide automatiquement)
class StudentInput(BaseModel):
    age: int = 17
    studytime: int = 2    # 1-4 (heures/semaine)
    failures: int = 0    # Nombre d'échecs passés
    absences: int = 6    # Absences
    G1: int = 10          # Note 1er trimestre
    G2: int = 10          # Note 2ème trimestre
    # + autres champs (school, sex, address...)

# Chargement des modèles au démarrage (lifespan)
@asynccontextmanager
async def lifespan(app):
    ensure_model()                                # Entraîne si absent
    _models["rf"]     = joblib.load("models/rf_classifier.pkl")
    _models["kmeans"] = joblib.load("models/kmeans.pkl")
    _models["scaler"] = joblib.load("models/scaler.pkl")
    yield

app = FastAPI(title="ML Service", lifespan=lifespan)

# Endpoint predict — Random Forest Classifier
@app.post("/predict")
def predict(student: StudentInput):
    X = _to_pca_vector(student)           # Normalisation + PCA
    pred  = int(_models["rf"].predict(X)[0])
    proba = _models["rf"].predict_proba(X)[0]
    return {
        "prediction":       "pass" if pred == 1 else "fail",
        "probability_pass": round(float(proba[1]), 4),
        "probability_fail": round(float(proba[0]), 4),
    }

# Endpoint cluster — K-Means (k=3)
@app.post("/cluster")
def cluster(student: StudentInput):
    X = _to_pca_vector(student)
    cluster_id = int(_models["kmeans"].predict(X)[0])
    labels = ["At-Risk", "Average", "High-Performing"]
    return { "cluster": cluster_id, "label": labels[cluster_id] }

# Endpoint analyze — predict + cluster en une seule requête
@app.post("/analyze")
def analyze(student: StudentInput):
    return { "prediction": predict(student), "profile": cluster(student) }

  private readonly claimApi  = environment.claimApiUrl;   // http://localhost:8080/api
  private readonly retakeApi = environment.retakeApiUrl;  // http://localhost:8080/api

  // GET /api/claims → Gateway → claim-service:8081/api/claims
  getAllClaims(studentId?: number) {
    const url = studentId
      ? `${this.claimApi}/claims?studentId=${studentId}`
      : `${this.claimApi}/claims`;
    return this.http.get<Claim[]>(url);
  }

  // POST /api/claims → crée une réclamation
  createClaim(claim: Partial<Claim>) {
    return this.http.post<Claim>(`${this.claimApi}/claims`, claim);
  }

  // PATCH /api/claims/{id}/authorize-retake → autorise le rattrapage
  authorizeRetake(id: number) {
    return this.http.patch<Claim>(`${this.claimApi}/claims/${id}/authorize-retake`, {});
  }

  // POST /api/retake-requests/from-claim/{claimId} → retake-service
  createRetakeFromClaim(claimId: number, courseName: string, reason: string, file: File) {
    const formData = new FormData();
    formData.append('retakeRequest', new Blob([JSON.stringify({courseName, reason})],
                   { type: 'application/json' }));
    formData.append('attachment', file);
    return this.http.post(`${this.retakeApi}/retake-requests/from-claim/${claimId}`, formData);
  }
}

MlService — Communication avec le ML Service

typescript frontend/src/app/routes/claims/services/ml.service.ts 
@Injectable({ providedIn: 'root' })
export class MlService {
  private readonly mlApi      = environment.mlApiUrl;      // http://localhost:8080/api/ml
  private readonly studentApi = environment.studentApiUrl;  // http://localhost:8080

  // Étape 1 : récupère le profil académique depuis auth-service
  // GET /api/students/{userId}/academic-profile → Gateway → auth-service:8083
  getAcademicProfile(userId: number): Observable<AcademicProfile> {
    return this.http.get<AcademicProfile>(
      `${this.studentApi}/api/students/${userId}/academic-profile`
    );
  }

  // Étape 2 : analyse ML complète (pipe RxJS — chaîne les deux appels)
  // 1) GET profil → 2) POST /api/ml/analyze → Gateway (StripPrefix=2) → ml-service:5000/analyze
  analyzeStudent(userId: number): Observable<MlAnalysis> {
    return this.getAcademicProfile(userId).pipe(
      switchMap(profile =>
        this.http.post<MlAnalysis>(`${this.mlApi}/analyze`, {
          G1: profile.g1, G2: profile.g2,
          age: profile.age, failures: profile.failures,
          absences: profile.absences, studytime: profile.studytime,
        })
      )
    );
  }
}

Intercepteur HTTP — Injection automatique du JWT

Angular injecte automatiquement le token JWT dans toutes les requêtes HTTP grâce à un intercepteur :

typescript Pattern — intercepteur JWT Angular 
// L'intercepteur récupère le token du localStorage et l'ajoute au header
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = localStorage.getItem('token');
  if (token) {
    const cloned = req.clone({
      headers: req.headers.set('Authorization', `Bearer ${token}`)
    });
    return next(cloned);
  }
  return next(req);
};
